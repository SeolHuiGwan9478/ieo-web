# 운영자 페이지: 차주 서류 심사 인계

이 문서는 이에오 운영자가 쓰는 관리자 페이지의 **차주 서류 심사** 기능을 만들 개발자를 위한 문서다. 2026-11-09에 설계안으로 쓰였고, 같은 날 서버 API와 운영자 화면을 구현했고, 사업자등록증은 국세청 진위확인 API로 반자동 확인한다. 무엇이 됐고 무엇이 남았는지는 12장에 있다.

- 프로젝트·서버 연동 규칙(토큰, 오류 형식, 시각 등): [03_어드민_인계.md](https://github.com/SeolHuiGwan9478/ieo-app/blob/main/docs/design/03_어드민_인계.md) 1장·4장
- 관련 요구사항: [../requirements/08_계정_차량.md](https://github.com/SeolHuiGwan9478/ieo-app/blob/main/docs/requirements/08_계정_차량.md), [../requirements/11_배차.md](https://github.com/SeolHuiGwan9478/ieo-app/blob/main/docs/requirements/11_배차.md)

> **주선사 콘솔과 다른 화면이다.** 주선사 콘솔은 주선사 회사가 쓰고, 이 페이지는 이에오 운영자만 쓴다. 차주의 면허증·사업자등록증을 다루므로 주선사 계정이 접근할 수 있으면 안 된다.

## 1. 왜 필요한가

화물맨과 카카오T 트럭커는 모두 차주에게 서류를 받고 사람이 심사한 뒤 이용을 승인한다. 이에오도 배차를 받는 차주가 실제 자격을 갖췄는지 확인해야 주선사가 믿고 배차할 수 있다.

운영자가 할 일은 하나다. **제출된 서류를 보고, 승인하거나 이유를 적어 반려한다.**

## 2. 현재 상태

| 항목 | 상태 |
|---|---|
| 운영자 역할(`ADMIN`)과 운영자 로그인 | **있음.** `UserRole.ADMIN`, `/api/admin/**`은 `AdminInterceptor`가 운영자만 통과시킨다. 로그인은 콘솔 `/admin/login` (휴대폰 인증, 가입 없음) |
| 운영자 페이지 | **있음.** 주선사 콘솔 저장소 안 `/admin` (심사 목록, 차주별 상세, 승인·반려, 이력) |
| 서류 저장·상태 관리·심사 API | **있음.** 서버 `domain/document` (엔티티 `DriverDocument`·`DriverDocumentEvent`, 차주·운영자 API). 7장 |
| 사업자등록증 국세청 진위확인 | **있음 (반자동).** 차주가 적은 사업자번호·개업일·대표자를 국세청 API로 맞춰 보고 결과를 서류에 붙인다. 승인·반려는 운영자가 정한다. 키가 없으면 건너뛰고, 시연은 스텁으로 한다. 12장 |
| 차주 정보 | `Driver`에 면허번호 칸만 있음. 서류는 별도 테이블 |
| 파일 저장 | `FileStorage` 있음. 로컬 디스크 구현만 있어 운영 전 클라우드 구현·저장 암호화 필요 |
| 폰 앱 서류 촬영 화면 | 없음. 이 문서와 별도로 만든다. 인수증 촬영 흐름을 재사용할 수 있다. 지금은 `scripts/seed-documents.py`가 차주 API로 가짜 서류를 올린다 |

## 3. 전체 흐름

```
차주(폰 앱)                     서버                      운영자(이 페이지)
서류 촬영·제출  ───────────▶  심사 대기
                                 │  ──────────────────▶  목록에서 열람
                                 │  ◀──────────────────  서류별 승인 / 반려(사유)
승인 알림 또는  ◀───────────  결과 저장
반려 사유 확인
반려된 서류만 다시 제출 ─────▶ 심사 대기 (다시 목록에)
```

필수 서류가 모두 승인되면 차주는 "인증됨"이 되고 배차를 요청할 수 있다.

## 4. 심사 대상 서류

| 서류 | 구분 | 운영자가 확인할 것 |
|---|---|---|
| 사업자등록증 | 필수 | 글씨가 읽히는가, 상호·사업자번호·대표자, 입력한 번호·개업일·대표자가 사진과 같은가, 대표자와 가입자 이름 일치. 국세청 진위확인 결과(일치·불일치·휴업·폐업)를 참고한다 |
| 자동차등록증 | 필수 | 차량 번호가 앱에 등록한 번호와 일치, 소유자, 사업용 차량 여부 |
| 운전면허증 | 필수 | 이름 일치, 유효한 면허, 차종에 맞는 면허 종류 |
| 화물운송종사 자격증 | 필수 | 이름 일치, 자격 번호 |
| 위·수탁(지입) 계약서 | 조건부 | 사업자·차량 명의가 본인과 다를 때 받는다. 당사자와 차량 번호 일치 |
| 적재물배상책임보험증서 | 선택 | 보험 기간, 차량 번호 |

필수 목록은 화물맨·트럭커 공통 항목을 기준으로 잡았다. 통장 사본은 화물맨이 이용료 자동출금용으로 받지만, 이에오는 자동출금이 없어 제외했다. 정산이나 요금제를 붙일 때 다시 정한다.

## 5. 상태

서류 하나의 상태:

| 상태 | 뜻 | 다음 |
|---|---|---|
| `PENDING` | 제출됨, 심사 전 | `APPROVED` 또는 `REJECTED` |
| `APPROVED` | 승인 | 차주가 새로 제출하면 새 건이 `PENDING` |
| `REJECTED` | 반려. 사유 필수 | 차주가 다시 제출하면 새 건이 `PENDING` |

- **차주의 인증 여부는 저장하지 않고 계산한다.** 필수 서류의 최신 제출 건이 모두 `APPROVED`면 인증됨이다.
- 재제출은 기존 건을 덮어쓰지 않고 새 건으로 만든다. 누가 무엇을 왜 반려했는지 남기기 위해서다.

## 6. 화면

### 6.1 운영자 로그인

- 일반 사용자 로그인과 분리하고, `ADMIN`만 들어올 수 있게 한다.
- 처음에는 서버에서 운영자 계정을 직접 지정해도 된다. 회원가입 화면은 만들지 않는다.

### 6.2 심사 목록

| 항목 | 내용 |
|---|---|
| 기본 보기 | 심사 대기를 **제출이 오래된 순서**로 |
| 탭 | 심사 대기 / 승인 / 반려 / 전체 |
| 열 | 차주 이름, 휴대폰(가운데 가림), 차량 번호, 서류 진행(예: 3/4), 제출 시각, 재제출 표시 |
| 검색 | 이름, 휴대폰 뒷자리, 차량 번호 |
| 메뉴 표시 | 심사 대기 건수 |

### 6.3 차주별 심사 상세

운영자가 화면을 오가지 않고 대조할 수 있게 **한 화면에서 서류 이미지와 비교 정보를 나란히** 보여 준다.

- **왼쪽:** 서류 이미지. 확대, 회전, 서류 간 이동
- **오른쪽:** 앱에 입력된 이름·휴대폰·차량 번호·톤수·차종, 서류별 상태, 이전 반려 이력
- **버튼:** 서류별 `승인`, `반려`
- 반려는 사유 선택이 필수다. 사유 문구는 차주에게 그대로 보인다.
- 처리 후 다음 심사 대기 건으로 넘어간다.
- 두 운영자가 동시에 처리하면 늦은 쪽은 409를 받고 "다른 운영자가 먼저 처리했어요"를 보여 준다.

### 6.4 반려 사유

| 코드 | 차주에게 보이는 문구 |
|---|---|
| `UNREADABLE` | 글씨가 잘 안 보여요. 밝은 곳에서 다시 찍어 주세요 |
| `CROPPED` | 서류 전체가 나오게 찍어 주세요 |
| `WRONG_DOCUMENT` | 다른 서류가 올라왔어요. 안내된 서류를 찍어 주세요 |
| `NAME_MISMATCH` | 가입한 이름과 서류의 이름이 달라요 |
| `VEHICLE_MISMATCH` | 등록한 차량 번호와 서류의 번호가 달라요 |
| `EXPIRED` | 유효 기간이 지났어요. 최신 서류를 올려 주세요 |
| `CONTRACT_REQUIRED` | 명의가 달라요. 위·수탁 계약서를 함께 올려 주세요 |
| `OTHER` | 운영자가 직접 입력 (필수) |

### 6.5 처리 이력

- 차주별로 제출, 승인, 반려, 서류 열람 기록을 시간순으로 보여 준다.
- 수정·삭제 기능은 두지 않는다.

## 7. 필요한 서버 API (제안)

2026-11-09에 아래 이름 그대로 구현했다 (서버 `domain/document`). 차주 쪽 API는 폰 앱에서 쓴다.

| 쓰는 곳 | API | 내용 |
|---|---|---|
| 차주 | `GET /api/drivers/me/documents` | 서류별 최신 상태, 반려 사유 |
| 차주 | `POST /api/drivers/me/documents` | multipart `file`(JPG·PNG 5MB), `type`. 사업자등록증은 `businessNumber`(123-45-67890)·`openedOn`(2020-01-31) 필수, `ownerName`은 가입자 이름과 다를 때만. 새 건 생성, 응답의 `businessCheck`에 국세청 조회 결과. 같은 종류가 심사 중이면 409 `DOCUMENT_409_PENDING`, 사업자 정보가 틀리면 400 `DOCUMENT_400_BUSINESS` |
| 차주 | `GET /api/drivers/me/documents/{id}/file` | 내가 올린 서류 사진 |
| 운영자 | `GET /api/admin/driver-documents?status&q&page&size` | 심사 목록. 차주 한 명이 한 줄. `status`는 PENDING(기본)·APPROVED·REJECTED·ALL, `q`는 이름·휴대폰 뒷자리·차량 번호 |
| 운영자 | `GET /api/admin/drivers/{driverId}/documents` | 상세, 비교 정보, 이력. 사업자등록증 건에는 `businessCheck`(입력값·국세청 결과) |
| 운영자 | `GET /api/admin/driver-documents/{id}/file` | 이미지. **열람 기록을 남긴다** |
| 운영자 | `POST /api/admin/driver-documents/{id}/approve` | 승인 |
| 운영자 | `POST /api/admin/driver-documents/{id}/business-check` | 국세청 진위확인 다시 조회 (심사 대기인 사업자등록증만). 응답은 서류 한 건 |
| 운영자 | `POST /api/admin/driver-documents/{id}/reject` | `{ reasonCode, note? }` |

서버에 함께 필요한 것:

- **됨.** `ADMIN` 역할과 `/api/admin/**` 권한 검사: `AdminInterceptor`가 `AuthInterceptor` 뒤에 돌며 운영자가 아니면 403 `ADMIN_403_ROLE`. 가입(`/api/auth/signup`)으로는 ADMIN을 만들 수 없다.
- **아직.** 배차 요청(`POST /api/orders/{id}/requests`)에서 인증 여부 확인. 폰 앱에 제출 화면이 생기기 전에 막으면 모든 차주가 배차를 못 받으므로 앱 화면과 함께 켠다. 인증 여부는 `GET /api/drivers/me/documents`의 `verified`로 이미 계산된다.
- **아직.** 결과를 차주에게 보내는 알림. 지금 `Notification`은 배차 요청에 묶여 있어 서류용 종류를 더하려면 구조를 넓혀야 한다. 당분간 폰 앱이 위 API로 상태를 본다.
- **됨.** 서류 파일은 `/api/public` 아래에 두지 않는다. 운영자와 본인만 로그인한 API로 받고, 운영자가 열 때마다 `VIEWED` 이력이 남는다.

## 8. 보안·개인정보

면허증과 사업자등록증에는 민감한 정보가 들어 있다. 운영자 페이지에서 가장 조심해야 할 부분이다.

- 서류 열람은 `ADMIN`만, 모든 열람을 누가·언제·무엇을 기준으로 기록한다.
- 파일은 암호화해 저장하고, 이미지 URL은 인증 없이 열리지 않게 한다.
- 목록에는 이미지를 미리 보여 주지 않는다. 상세에 들어갔을 때만 불러온다.
- 화면에서 휴대폰 등 불필요한 정보는 가려서 보여 준다. 사업자번호는 사진과 대조해야 해서 차주별 상세에서만 보여 주고 목록에는 내지 않는다.
- 운영자 페이지는 다운로드 버튼을 두지 않는다.
- 탈퇴 시 서류 처리 기준을 정한다. 지금 `UserService`의 탈퇴 처리에 서류 삭제를 추가해야 한다.

## 9. 완료 기준

- [x] `ADMIN`이 아닌 계정은 페이지와 `/api/admin/**`에 접근할 수 없다 (테스트 `AdminDocumentControllerTest`)
- [x] 심사 대기 건이 오래된 순서로 보인다
- [x] 서류 이미지와 앱 입력 정보를 한 화면에서 대조할 수 있다
- [x] 반려할 때 사유 없이는 저장되지 않는다 (기타는 직접 적어야 한다)
- [ ] 반려 사유가 폰 앱에 그대로 표시되고, 반려된 서류만 다시 낼 수 있다 — API는 `rejectMessage`를 주고 심사 중인 종류만 다시 못 낸다. 폰 앱 화면은 아직
- [ ] 필수 서류가 모두 승인되면 차주가 배차를 요청할 수 있고, 하나라도 빠지면 거절된다 — 인증 여부(`verified`)는 계산한다. 배차 요청 차단은 아직 (7장)
- [x] 동시 처리 시 늦은 쪽에 409 안내가 뜬다 (`DOCUMENT_409_REVIEWED`)
- [x] 서류 열람·승인·반려가 모두 이력에 남는다
- [x] 로그인 없이 서류 이미지 주소를 열 수 없다
- [x] 사업자등록증은 국세청 진위확인 결과가 제출 응답·목록·상세에 보이고, 불일치·휴업·폐업이면 눈에 띄게 표시된다. 운영자가 다시 조회할 수 있다

## 10. 결정이 필요한 것

| 항목 | 내용 | 담당 |
|---|---|---|
| 서류 받는 시점 | **권장: 첫 배차 요청 때.** 가입 때 받으면 중간 이탈이 늘 수 있다. 지금 요구사항 ACC-003은 "사업자 정보는 장부 내보내기 때만 요청"이라 함께 고쳐야 한다 | 기획 |
| 공모전 데모 범위 | 마감 전에는 서류 제출·상태 화면과 시험용 승인까지만 할지 | 기획 |
| 법적 검토 | 운전면허번호 등 민감 정보의 수집 근거, 별도 동의 문구, 보관 기간, 파기 절차 | 법무 확인 필요 |
| 심사 목표 시간 | 평일 몇 시간 안에 처리할지, 주말 처리 여부 | 운영 |
| 진위 확인 | **정함(2026-11-09): 사업자등록증은 국세청 진위확인 API로 반자동.** 결과는 참고용이고 승인·반려는 운영자가 정한다. 면허증·자격증은 공개 API가 없어 사람이 본다 | 기획 |
| 주선사 사업자 심사 | 주선사 가입도 운영자가 승인할지. 이 문서 범위에는 넣지 않았다 | 기획 |

## 12. 구현 현황 (2026-11-09)

### 어디에 있나

- 서버 `ieo-server`: `domain/document` (enums·entity·repository·service·controller, `business/`는 국세청 클라이언트·시연용 스텁·설정), `global/auth/AdminInterceptor`, `UserRole.ADMIN`. 테스트 `AdminDocumentControllerTest` 4건, `NtsBusinessLookupClientTest` 4건
- 콘솔 `ieo-console`: `src/admin/` (문지기 `RequireAdmin`, 틀 `AdminLayout`), `src/pages/admin/` (로그인, 심사 목록, 차주별 상세), `src/api/admin.ts`
- 시드: `ieo-server/scripts/seed-documents.py`, `scripts/users-role-admin.sql`, `scripts/driver-documents-business-check.sql`

### 운영자 계정 만들기

가입으로는 못 만든다. 둘 중 하나로 만든다.

- `python scripts/seed-documents.py --psql <psql 경로>`: 운영자 010-0000-0099([시연] 운영자)를 만들고, `seed-console.py`가 만든 [시연] 차주 6명에게 가짜 서류를 올려 승인·반려·대기 상태를 섞어 둔다. `--reset`을 붙이면 시연 차주의 서류를 지우고 다시 올린다. 서버 주소는 `IEO_API_BASE`
- SQL로 직접: `scripts/users-role-admin.sql`을 먼저 적용한 뒤 `INSERT INTO users (phone, name, role, status, created_at, updated_at) VALUES ('휴대폰', '이름', 'ADMIN', 'ACTIVE', now(), now())`

이미 있던 DB는 `users.role`의 CHECK 제약에 ADMIN이 없어서 `users-role-admin.sql`이 꼭 필요하다. Hibernate의 `ddl-auto: update`는 기존 제약을 고치지 않는다. 같은 이유로 반려 사유·이력 종류가 늘어난 뒤에는 `driver-documents-business-check.sql`도 적용한다 (시드가 함께 적용한다).

### 국세청 진위확인 설정

- 키: 공공데이터포털에서 [국세청_사업자등록정보 진위확인 및 상태조회 서비스](https://www.data.go.kr/data/15081808/openapi.do)를 활용신청(자동 승인)하고 "일반 인증키 (Decoding)"을 `.env`의 `NTS_SERVICE_KEY`에 넣는다. 무료다
- 키가 없으면 조회하지 않고 서류에 "조회 안 함"이 남는다. 운영자는 눈으로만 본다
- `NTS_STUB=true`면 키 없이 시연용 가짜 결과를 쓴다. 사업자번호 아홉째 자리로 정한다: 0~6 계속사업자, 7 휴업, 8 폐업, 9 불일치. 화면에 "시연용 응답"이 붙는다
- 시연 차주의 번호는 가짜라 실제 키로는 전부 불일치가 나온다. 시연은 스텁으로 하거나, 차주 한 명에 실제 사업자 정보를 넣는다
- 진위확인은 번호·개업일·대표자 조합이 국세청에 등록돼 있는지만 답한다. 올린 사진이 진짜인지, 사진의 값과 입력값이 같은지는 운영자가 본다

### 동작 요약

- 차주: 종류별로 사진(JPG·PNG 5MB)을 올리면 심사 대기가 된다. 같은 종류가 심사 중이면 409. 반려·승인 뒤에는 새 건으로 다시 낼 수 있고 이전 건은 이력으로 남는다
- 운영자: 목록(차주 한 줄, 탭 심사 대기/승인/반려/전체, 이름·휴대폰 뒷자리·차량 번호 검색, 심사 대기는 오래 기다린 순) → 상세(사진 확대·회전·서류 간 이동, 앱 입력값 대조, 서류별 확인 항목, 처리 이력) → 승인 또는 반려(사유 필수, 기타는 직접 입력). 다 처리하면 "다음 심사 대기 건"으로 넘어간다
- 사업자등록증: 사진과 함께 사업자번호·개업일(·대표자, 비우면 가입자 이름)을 보내면 서버가 국세청 진위확인을 바로 돌려 결과를 서류에 붙인다 (`businessCheck`). 번호는 검증 숫자까지 맞아야 받는다. 결과(일치·불일치·휴업·폐업·조회 실패·조회 안 함)는 제출 응답·목록·상세에 보이고 운영자가 "다시 조회"할 수 있다. 반려 사유에 국세청 불일치·휴업·폐업이 있고 반려 창에서 미리 골라진다. 조회는 `BUSINESS_CHECKED` 이력으로 남는다
- 인증 여부는 저장하지 않고 계산한다: 필수 4종의 최신 제출이 모두 승인이면 인증됨 (`verified`)
- 동시 처리: `@Version`과 상태 검사로 늦은 쪽이 409를 받고, 화면은 "다른 운영자가 먼저 처리했어요"를 띄우며 새로 고친다
- 열람 기록: 운영자가 사진을 열 때마다 `VIEWED` 이력. 휴대폰은 운영자 화면에 가운데를 가려 보낸다. 탈퇴하면 서류 파일과 이력을 지운다 (`UserService.withdraw`)

- 목록은 서류 전체를 읽어 메모리에서 차주별로 묶는다. 차주가 수천 명이 되면 DB 집계 쿼리로 바꾼다
