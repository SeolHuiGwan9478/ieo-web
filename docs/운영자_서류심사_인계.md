# 운영자 페이지: 차주 서류 심사 인계

이 문서는 이에오 운영자가 쓰는 관리자 페이지의 **차주 서류 심사** 기능을 만들 개발자를 위한 문서다. 2026-11-09 기준이며, 코드 작업 전의 설계안이다.

- 프로젝트·서버 연동 규칙(토큰, 오류 형식, 시각 등): [03_어드민_인계.md](https://github.com/SeolHuiGwan9478/ieo-app/blob/main/docs/design/03_어드민_인계.md) 1장·4장
- 관련 요구사항: [../requirements/08_계정_차량.md](https://github.com/SeolHuiGwan9478/ieo-app/blob/main/docs/requirements/08_계정_차량.md), [../requirements/11_배차.md](https://github.com/SeolHuiGwan9478/ieo-app/blob/main/docs/requirements/11_배차.md)

> **주선사 콘솔과 다른 화면이다.** 주선사 콘솔은 주선사 회사가 쓰고, 이 페이지는 이에오 운영자만 쓴다. 차주의 면허증·사업자등록증을 다루므로 주선사 계정이 접근할 수 있으면 안 된다.

## 1. 왜 필요한가

화물맨과 카카오T 트럭커는 모두 차주에게 서류를 받고 사람이 심사한 뒤 이용을 승인한다. 이에오도 배차를 받는 차주가 실제 자격을 갖췄는지 확인해야 주선사가 믿고 배차할 수 있다.

운영자가 할 일은 하나다. **제출된 서류를 보고, 승인하거나 이유를 적어 반려한다.**

## 2. 현재 상태

| 항목 | 상태 |
|---|---|
| 운영자 역할(`ADMIN`)과 운영자 로그인 | 없음 |
| 운영자 페이지 | 없음 |
| 서류 저장·상태 관리·심사 API | 없음 |
| 차주 정보 | `Driver`에 면허번호 칸만 있음 |
| 파일 저장 | `FileStorage` 있음. 로컬 디스크 구현만 있어 운영 전 클라우드 구현 필요 |
| 폰 앱 서류 촬영 화면 | 없음. 이 문서와 별도로 만든다. 인수증 촬영 흐름을 재사용할 수 있다 |

## 3. 전체 흐름

```
차주(폰 앱)                     서버                      운영자(이 페이지)
서류 촬영·제출  ───────────▶  심사 대기
                                 │  ──────────────────▶  목록에서 열람
                                 │  ◀──────────────────  서류별 승인 / 반려(사유)
승인 알림 또는  ◀───────────  결과 저장
반려 사유 확인
반려된 서류만 다시 제출 ─────▶ 심사 대기 (다시 목록에)
```

필수 서류가 모두 승인되면 차주는 "인증됨"이 되고 배차를 요청할 수 있다.

## 4. 심사 대상 서류

| 서류 | 구분 | 운영자가 확인할 것 |
|---|---|---|
| 사업자등록증 | 필수 | 글씨가 읽히는가, 상호·사업자번호·대표자, 대표자와 가입자 이름 일치 |
| 자동차등록증 | 필수 | 차량 번호가 앱에 등록한 번호와 일치, 소유자, 사업용 차량 여부 |
| 운전면허증 | 필수 | 이름 일치, 유효한 면허, 차종에 맞는 면허 종류 |
| 화물운송종사 자격증 | 필수 | 이름 일치, 자격 번호 |
| 위·수탁(지입) 계약서 | 조건부 | 사업자·차량 명의가 본인과 다를 때 받는다. 당사자와 차량 번호 일치 |
| 적재물배상책임보험증서 | 선택 | 보험 기간, 차량 번호 |

필수 목록은 화물맨·트럭커 공통 항목을 기준으로 잡았다. 통장 사본은 화물맨이 이용료 자동출금용으로 받지만, 이에오는 자동출금이 없어 제외했다. 정산이나 요금제를 붙일 때 다시 정한다.

## 5. 상태

서류 하나의 상태:

| 상태 | 뜻 | 다음 |
|---|---|---|
| `PENDING` | 제출됨, 심사 전 | `APPROVED` 또는 `REJECTED` |
| `APPROVED` | 승인 | 차주가 새로 제출하면 새 건이 `PENDING` |
| `REJECTED` | 반려. 사유 필수 | 차주가 다시 제출하면 새 건이 `PENDING` |

- **차주의 인증 여부는 저장하지 않고 계산한다.** 필수 서류의 최신 제출 건이 모두 `APPROVED`면 인증됨이다.
- 재제출은 기존 건을 덮어쓰지 않고 새 건으로 만든다. 누가 무엇을 왜 반려했는지 남기기 위해서다.

## 6. 화면

### 6.1 운영자 로그인

- 일반 사용자 로그인과 분리하고, `ADMIN`만 들어올 수 있게 한다.
- 처음에는 서버에서 운영자 계정을 직접 지정해도 된다. 회원가입 화면은 만들지 않는다.

### 6.2 심사 목록

| 항목 | 내용 |
|---|---|
| 기본 보기 | 심사 대기를 **제출이 오래된 순서**로 |
| 탭 | 심사 대기 / 승인 / 반려 / 전체 |
| 열 | 차주 이름, 휴대폰(가운데 가림), 차량 번호, 서류 진행(예: 3/4), 제출 시각, 재제출 표시 |
| 검색 | 이름, 휴대폰 뒷자리, 차량 번호 |
| 메뉴 표시 | 심사 대기 건수 |

### 6.3 차주별 심사 상세

운영자가 화면을 오가지 않고 대조할 수 있게 **한 화면에서 서류 이미지와 비교 정보를 나란히** 보여 준다.

- **왼쪽:** 서류 이미지. 확대, 회전, 서류 간 이동
- **오른쪽:** 앱에 입력된 이름·휴대폰·차량 번호·톤수·차종, 서류별 상태, 이전 반려 이력
- **버튼:** 서류별 `승인`, `반려`
- 반려는 사유 선택이 필수다. 사유 문구는 차주에게 그대로 보인다.
- 처리 후 다음 심사 대기 건으로 넘어간다.
- 두 운영자가 동시에 처리하면 늦은 쪽은 409를 받고 "다른 운영자가 먼저 처리했어요"를 보여 준다.

### 6.4 반려 사유

| 코드 | 차주에게 보이는 문구 |
|---|---|
| `UNREADABLE` | 글씨가 잘 안 보여요. 밝은 곳에서 다시 찍어 주세요 |
| `CROPPED` | 서류 전체가 나오게 찍어 주세요 |
| `WRONG_DOCUMENT` | 다른 서류가 올라왔어요. 안내된 서류를 찍어 주세요 |
| `NAME_MISMATCH` | 가입한 이름과 서류의 이름이 달라요 |
| `VEHICLE_MISMATCH` | 등록한 차량 번호와 서류의 번호가 달라요 |
| `EXPIRED` | 유효 기간이 지났어요. 최신 서류를 올려 주세요 |
| `CONTRACT_REQUIRED` | 명의가 달라요. 위·수탁 계약서를 함께 올려 주세요 |
| `OTHER` | 운영자가 직접 입력 (필수) |

### 6.5 처리 이력

- 차주별로 제출, 승인, 반려, 서류 열람 기록을 시간순으로 보여 준다.
- 수정·삭제 기능은 두지 않는다.

## 7. 필요한 서버 API (제안)

이름은 구현하면서 바꿔도 된다. 차주 쪽 API는 폰 앱에서 쓴다.

| 쓰는 곳 | API | 내용 |
|---|---|---|
| 차주 | `GET /api/drivers/me/documents` | 서류별 최신 상태, 반려 사유 |
| 차주 | `POST /api/drivers/me/documents` | multipart `file`, `type`. 새 건 생성 |
| 운영자 | `GET /api/admin/driver-documents?status&q&page&size` | 심사 목록 |
| 운영자 | `GET /api/admin/drivers/{driverId}/documents` | 상세, 비교 정보, 이력 |
| 운영자 | `GET /api/admin/driver-documents/{id}/file` | 이미지. **열람 기록을 남긴다** |
| 운영자 | `POST /api/admin/driver-documents/{id}/approve` | 승인 |
| 운영자 | `POST /api/admin/driver-documents/{id}/reject` | `{ reasonCode, note? }` |

서버에 함께 필요한 것:

- `ADMIN` 역할과 `/api/admin/**` 권한 검사. 지금 인증 인터셉터는 `/api/auth/**`, `/api/public/**` 외 전부를 로그인 사용자에게 열어 주므로 역할 검사를 반드시 따로 넣는다.
- 배차 요청(`POST /api/orders/{id}/requests`)에서 인증 여부 확인. 미인증이면 전용 오류 코드로 거절한다.
- 결과를 차주에게 보내는 알림. 지금 `Notification`은 배차 요청에 묶여 있어 서류용 종류를 더하려면 구조를 넓혀야 한다.
- 서류 파일은 `/api/public` 아래에 두지 않는다. 인수증 사진과 달리 공개 URL을 만들면 안 된다.

## 8. 보안·개인정보

면허증과 사업자등록증에는 민감한 정보가 들어 있다. 운영자 페이지에서 가장 조심해야 할 부분이다.

- 서류 열람은 `ADMIN`만, 모든 열람을 누가·언제·무엇을 기준으로 기록한다.
- 파일은 암호화해 저장하고, 이미지 URL은 인증 없이 열리지 않게 한다.
- 목록에는 이미지를 미리 보여 주지 않는다. 상세에 들어갔을 때만 불러온다.
- 화면에서 휴대폰·사업자번호 등 불필요한 정보는 가려서 보여 준다.
- 운영자 페이지는 다운로드 버튼을 두지 않는다.
- 탈퇴 시 서류 처리 기준을 정한다. 지금 `UserService`의 탈퇴 처리에 서류 삭제를 추가해야 한다.

## 9. 완료 기준

- [ ] `ADMIN`이 아닌 계정은 페이지와 `/api/admin/**`에 접근할 수 없다
- [ ] 심사 대기 건이 오래된 순서로 보인다
- [ ] 서류 이미지와 앱 입력 정보를 한 화면에서 대조할 수 있다
- [ ] 반려할 때 사유 없이는 저장되지 않는다
- [ ] 반려 사유가 폰 앱에 그대로 표시되고, 반려된 서류만 다시 낼 수 있다
- [ ] 필수 서류가 모두 승인되면 차주가 배차를 요청할 수 있고, 하나라도 빠지면 거절된다
- [ ] 동시 처리 시 늦은 쪽에 409 안내가 뜬다
- [ ] 서류 열람·승인·반려가 모두 이력에 남는다
- [ ] 로그인 없이 서류 이미지 주소를 열 수 없다

## 10. 결정이 필요한 것

| 항목 | 내용 | 담당 |
|---|---|---|
| 서류 받는 시점 | **권장: 첫 배차 요청 때.** 가입 때 받으면 중간 이탈이 늘 수 있다. 지금 요구사항 ACC-003은 "사업자 정보는 장부 내보내기 때만 요청"이라 함께 고쳐야 한다 | 기획 |
| 공모전 데모 범위 | 마감 전에는 서류 제출·상태 화면과 시험용 승인까지만 할지 | 기획 |
| 법적 검토 | 운전면허번호 등 민감 정보의 수집 근거, 별도 동의 문구, 보관 기간, 파기 절차 | 법무 확인 필요 |
| 심사 목표 시간 | 평일 몇 시간 안에 처리할지, 주말 처리 여부 | 운영 |
| 진위 확인 | 사람 눈으로만 볼지, 국세청 사업자 상태 조회 등 외부 조회를 붙일지 | 기획 |
| 주선사 사업자 심사 | 주선사 가입도 운영자가 승인할지. 이 문서 범위에는 넣지 않았다 | 기획 |
| 운영자 페이지 위치 | 주선사 콘솔(`ieo-web`)과 저장소·배포 주소를 나눌지 | 담당 개발자 |
