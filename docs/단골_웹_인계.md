# 단골 차주 연결 웹 인계 (2026-11-13)

주선사 콘솔(ieo-web)의 **단골 차주(BRK-002)** 작업을 이어 맡을 분을 위한 문서다.

- 원본 요구사항: ieo-app `docs/requirements/07_주선사.md` BRK-002, `09_알림.md` "단골 연결 요청" 행
- 기준: 서버 `e389ac3`, 휴대폰 `6742a14`, 차량 앱 `d10f604`, 콘솔 `origin/main` `33a1712`

## 1. 정해진 것 (2026-11-13)

| 무엇 | 결정 |
|---|---|
| 수락·거절·해제 | **기사님 휴대폰 앱에서만** 한다. 수락은 "이 회사 운행 중 위치·도착 예정 시각 공유" 동의라서 차분히 읽고 고르게 한다 |
| 차량 앱 | 요청 창과 해제 버튼을 뺐다. 요청이 오면 배너와 음성으로 알려만 주고, 설정에서 받은 요청과 연결된 회사를 **보기만** 한다 |
| 기사님에게 알리는 법 | 이미 가입한 번호면 서버가 **앱 알림**(`DRIVER_LINK_REQUESTED`)을 보낸다. 휴대폰 알림함에서 누르면 단골 주선사 화면이 열린다 |
| 문자 | 보내지 않는다 (서버 `5850b07`, 문자는 로그인 인증번호만). 가입 전 번호는 그 번호로 가입하면 요청이 보인다 |
| 기한 | 요청은 7일 안에 답해야 하고, 지나면 만료 |
| 콘솔(주선사) 쪽 흐름 | 그대로다. 번호로 요청 → 대기 중 목록(7일, [취소]) → 연결되면 차주 목록, [해제]는 콘솔에서도 된다 |

## 2. 웹에서 고칠 것

| # | 할 일 | 급한 정도 | 고칠 곳 |
|---|---|---|---|
| 1 | 안내 문구를 휴대폰 기준으로. 지금: "차주는 차량 앱(정차 중)에서 요청을 수락해요. 가입 전 번호도 요청할 수 있어요. 문자는 보내지 않으니 요청한 사실을 따로 알려 주세요." → 바꿀 것: "차주는 이에오 휴대폰 앱에서 수락해요. 이미 가입한 차주에게는 앱 알림이 가고, 가입 전 번호는 그 번호로 가입하면 요청이 보여요. 문자는 보내지 않으니 요청한 사실을 따로 알려 주세요." | **꼭** (지금 문구가 틀림) | `src/pages/DriversPage.tsx:106` |
| 2 | 파일 위 주석 "차주가 차량 앱에서 수락" → "차주가 휴대폰 앱에서 수락" | 보통 | `src/pages/DriversPage.tsx:10` |
| 3 | (선택) 연결 요청 창에 "가입한 차주에게는 앱 알림이 가요" 한 줄 | 선택 | `DriversPage.tsx`의 `InviteModal` 안내 문장(`:137` 둘레) |

API와 응답 모양은 바뀌지 않았다. 콘솔이 쓰는 엔드포인트는 그대로다.

| 요청 | 설명 |
|---|---|
| `POST /api/brokers/me/driver-invitations` `{ "phone" }` | 연결 요청. 가입한 차주면 서버가 앱 알림을 보낸다 (콘솔이 할 일 없음) |
| `GET /api/brokers/me/driver-invitations` | 대기 중 요청 |
| `POST /api/brokers/me/driver-invitations/{linkId}/cancel` | 요청 취소 |
| `GET /api/brokers/me/drivers` | 연결된 차주 |
| `POST /api/brokers/me/drivers/{linkId}/unlink` | 해제 |

## 3. 나중에 (지금 할 일 아님)

- 휴대폰 푸시(FCM): Firebase 프로젝트가 생기면 앱이 꺼져 있어도 단골 요청 알림이 가게 한다. 콘솔 변경은 없다
- 주선사용 알림 목록(콘솔 종 아이콘): 기사님이 수락·거절했을 때 알려 주기. 지금은 대기 중 목록에서 사라지고 차주 목록에 생기는 것으로 안다
- 같이 운행한 기사님에게 단골 요청을 제안하기(번호 입력 없이): 논의만 했고 정하지 않았다
