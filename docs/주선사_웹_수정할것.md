## 1. 인수증 카드 (꼭) — 06 인계 25장

수하인 서명을 없앴다. 이제 기사님이 **결제 방식이 인수증인 운행**에서 종이 인수증을 휴대폰으로 찍어 [주선사에게 보내기]를 누른다. 보내면 주선사 담당자에게 문자가 간다 ("○○ 차량의 인수증 사진이 도착했어요. 콘솔 운행 상세에서 볼 수 있어요.").

**지금 콘솔은 이렇게 깨진다:** 서버가 `receipt`를 새 모양으로 주므로 `PROOF_STATUS[t.receipt.status]`가 `undefined`가 되고, [인수증 열기]의 `t.receipt.path`도 없어 링크가 깨진다. `/r/{token}` 페이지도 서버에서 없앴다.

### 응답 (`GET /api/brokers/me/trips`, `GET /api/brokers/me/trips/{id}`)

```ts
// 예전
receipt: { status, signerName, signedAt, hasPaperPhoto, issueNote, path, expiresAt } | null

// 지금. 기사님이 보낸 뒤에만 있다
receipt: {
  sentAt: string            // 보낸 시각
  photos: { id: number; path: string; uploadedAt: string }[]   // 1~5장
} | null
```

- `paymentType === 'RECEIPT'`인데 `receipt`가 `null`이면 **아직 안 보냈다**. 선불·착불이면 인수증이 없는 운행이다
- 만료가 없다 (예전 `expiresAt` 없음). 정산할 때 언제든 본다

### 사진 받기

- `photos[].path` = `/api/brokers/me/trips/{tripId}/receipt-photos/{photoId}` (JPG 또는 PNG)
- 다른 API처럼 **`Authorization: Bearer` 헤더가 있어야** 받는다. `<img src={path}>`로는 헤더를 못 붙이니 `fetch`(콘솔의 `api` 클라이언트)로 받아 `URL.createObjectURL(blob)`을 `src`에 넣는다. 화면을 떠날 때 `URL.revokeObjectURL`
- 보내기 전이거나 다른 회사 운행이면 404

### 고칠 곳

| 파일 | 지금 | 바꿀 것 |
|---|---|---|
| `src/api/trips.ts:32-40` | `interface Receipt { status, signerName, signedAt, hasPaperPhoto, issueNote, path, expiresAt }` | `interface Receipt { sentAt: string; photos: { id: number; path: string; uploadedAt: string }[] }` |
| `src/api/trips.ts:2` | `DeliveryProofStatus` import | 쓰지 않으면 지운다 |
| `src/api/types.ts:89-94` | `PROOF_STATUS` (서명 전·서명 완료·종이 인수증 사진·전달 완료) | 지운다. `DeliveryProofStatus` 타입도 지운다 |
| `src/pages/trips/TripDetailPage.tsx:108-125` | "전자인수증" 카드: 상태·수하인·서명 시각·종이 인수증·이상 사항, [인수증 열기], 링크 만료 | 아래 화면처럼 |
| `src/pages/trips/TripDetailPage.tsx:10` | 주석 "전자인수증" | "인수증 사진" |

### 화면 제안 (운행 상세의 카드)

- 제목: **인수증**
- 보냈으면: "11월 12일 17:20 · 사진 2장" + 썸네일(가로로, 누르면 크게 보기. 여러 장이면 이전·다음). 크게 보기에서 새 탭으로 열거나 내려받기가 있으면 정산 담당자가 편하다
- 인수증 결제인데 아직 안 보냈으면: 회색 글씨로 "기사님이 아직 종이 인수증을 보내지 않았어요"
- 선불·착불: 카드를 숨기거나 "인수증이 없는 운행이에요"
- 운행 목록에 칸을 하나 둔다면 인수증 결제 운행에 "인수증 보냄 / 안 보냄" 정도

## 4. 짐을 실은 뒤 취소 안내 (선택) — 06 인계 24장

- 기사님은 운송 중·하차지 운행을 앱에서 취소하지 못한다 (`TRIP_409_LOADED`). 그때는 주선사가 콘솔에서 취소한다 (주선사 취소는 그대로 된다)
- `OrderDetailPage.tsx:170`의 취소 창(`CancelModal`)에, 운행이 운송 중·하차지면 "짐을 실은 뒤에는 기사님이 앱에서 취소할 수 없어 연락이 올 수 있어요" 한 줄
- 늦은 취소 3번(30일)이면 기사님이 7일 동안 배차 요청을 못 한다 (`DISPATCH_403_RESTRICTED`). 콘솔이 보는 `lateCancelCount`는 그대로라 바꿀 것은 없다

## 5. 추천으로 들어온 배차 요청 (선택) — 06 인계 21장

배차 요청에 `isRecommendation`이 저장된다 (차를 세웠을 때 추천 카드에서 요청). 콘솔에서 "추천으로 들어온 요청"을 보여 주고 싶으면 서버 응답에 이 값을 더해 달라고 말해 주면 된다. 지금은 응답에 없다.
